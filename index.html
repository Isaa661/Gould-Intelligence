NEW · NVIDIA GR00T N1.7 · OCTOBER 2026

Closer predictions of robot-arm movements.

In a new offline evaluation on six previously unused recorded episodes, Gould Intelligence reduced overall end-effector prediction error compared with the original NVIDIA GR00T N1.7 model. We evaluated 24 short prediction windows while keeping the original NVIDIA model weights unchanged.

5.10%

0.81%

6

24

What this means: The combined end-effector prediction error was lower, but position-only error during commanded motion improved by just 0.05%. Better physical robot movement, task success and safety have not been demonstrated. This is independent research, not an NVIDIA-conducted or endorsed study.

NEW · UNITREE WALKING SIMULATIONS · OCTOBER 2026

More accurate speed tracking in simulated walking.

In separate 12-second MuJoCo stress tests, experimental Gould Intelligence corrections helped Unitree G1 and H1 walking controllers follow changing speed commands more closely. Each was compared against its original controller in seven paired scenarios, including simulated disturbances.

20.77%
lower G1 simulated speed-tracking error
12.68%
lower H1 simulated speed-tracking error
7 / 7
scenarios improved for each controller
0
additional simulated falls in these tests
Important: These results measure speed-tracking accuracy in computer simulations, not physical-robot task success or safety. The original controller weights were unchanged. A third Unitree controller kept its original commands because an experimental correction did not meet our acceptance requirements. These results are from separate experiments and were not conducted or endorsed by Unitree.

POTENTIAL ROBOT TEST PROJECT

Start with one robot system and one clear goal.

A first project could use computer simulation, with no need to bring a physical robot.

What we'd need

  • A robot simulator or remote testing environment
  • Access to the existing robot control system
  • Details of the robot's sensor inputs and movement commands
  • A way to repeat the same test
  • A clear measure of how well the robot performs
  • Information about how quickly commands must run
  • Agreed rules for what counts as success

What you'd receive

  • Results from the original robot system
  • A report on where it struggles
  • An assessment of whether improvements are supported
  • Results of any tested changes
  • Checks that the original system is preserved where needed
  • Results on separate tests chosen in advance
  • A clear final report explaining what worked and what didn't
CLEAR RESULTS, NOT JUST BIG NUMBERS

We report setbacks as well as successes.

We decide how to judge an experiment before seeing its final results. We keep the original robot software as a comparison and don't call a change successful unless the evidence supports it.
